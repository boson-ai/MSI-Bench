# Interaction-Bench Taxonomy

## Unit of evaluation

One manifest row is one audio scene plus one assistant decision target. The model receives audio and a task instruction. The expected output is either:

1. a text answer, if the assistant should engage; or
2. a silence/non-engagement decision, if the speech is not addressed to the assistant or the assistant should wait.

## Expected actions

| Action | Meaning | Typical failure |
| --- | --- | --- |
| `respond` | The assistant is addressed and should answer. | Missed engagement or wrong answer. |
| `ignore` | Speech is not addressed to the assistant. | False engagement / hallucinated response. |
| `wait` | The assistant should not answer yet because the turn is incomplete, interrupted, or socially premature. | Premature response. |
| `clarify` | The assistant should ask a clarification question instead of guessing. | Hallucinated intent or wrong addressee. |
| `incorporate` | A new participant explicitly joins and addresses the assistant; the assistant should include them. | Ignores participant or treats them as bystander. |

## Interaction classes

| Class | Expected action(s) | Description |
| --- | --- | --- |
| `must_respond` | `respond` | Direct user request or valid assistant-directed question. |
| `must_ignore` | `ignore` | Side conversation, bystander speech, user talking to another person. |
| `must_wait` | `wait` | Pause, interruption, backchannel, incomplete turn, or conversationally unsafe timing. |
| `must_clarify` | `clarify` | Conflicting requests, unclear addressee, ambiguous reference. |
| `must_incorporate` | `incorporate` | Third party explicitly addresses the assistant and joins the interaction. |

## Scenario domains

- `meeting`: multiple participants, agenda discussion, side conversations, explicit assistant turns.
- `car`: driver/passenger requests, road noise, honks, navigation/media/communication tasks.
- `wearable`: egocentric audio from glasses/headsets, motion, bystanders, public spaces.
- `household`: TV, appliances, family members, delivery interruptions.
- `public`: street, cafe, store, transit, crowd and bystander speech.
- `phone_or_codec`: telephony, Bluetooth, lossy compression, bandwidth-limited speech.
- `synthetic_or_seed`: seed examples imported from existing datasets before full scenario mapping.

## Acoustic perturbation families

| Family | Examples | Suggested sweep variables |
| --- | --- | --- |
| `overlap` | competing speech, crosstalk, side conversation | overlap ratio, target-to-interferer ratio |
| `reverb` | meeting room, hallway, kitchen, car cabin | RT60, room profile |
| `transient_noise` | honks, sirens, knocks, phone sounds | event type, onset, peak SNR |
| `continuous_noise` | wind, road, HVAC, crowd, TV, music | SNR, stationarity, source category |
| `codec_channel` | phone codec, Bluetooth, compression, far-field mic | codec, bitrate, sample rate, mic distance |
| `egocentric_motion` | head turns, walking, changing speaker distance | motion type, distance, channel availability |

## Label confidence

Seed rows imported from existing datasets can contain inferred labels because source datasets were not designed exactly for this taxonomy. Use:

- `gold`: directly annotated for this benchmark definition;
- `source`: source dataset provides an equivalent label;
- `inferred`: mapping was inferred from source task/folder names and should be audited;
- `synthetic`: generated by perturbation or scenario script and needs spot checks.
